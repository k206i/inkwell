# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

«Чернильница» (`ru.kliukin.inkwell`): мобильное приложение для тренировки грамотности на текстах классической литературы (Ionic 8 + Vue 3 + Capacitor 8). UI-тексты на русском языке. Работает без сервера, рекламы и аналитики, всё хранится на устройстве.

Стек и правила повторяют приложение «День рождения» (`k206i/your-birthday`).

### Задания

- Абзацы из классики с пропущенными буквами и пробелами: пользователь вставляет нужные символы.
- Викторины: выбрать правильное написание.
- Диктанты: та же механика, текст на слух.

### Игровая механика

- Перо вмещает ограниченный запас чернил, каждый вставленный символ тратит каплю. Исправление стоит дороже: стереть и написать заново.
- Пустое перо нужно макнуть в чернильницу (короткая анимация).
- Клякса предсказуемая, не по случайному шансу: каждая ошибка набухает каплей на пере, на третьей капля срывается.
- Клякса падает рядом с последним исправлением и не закрывает ещё не заполненные пропуски.
- Страница без клякс становится чистовиком, с кляксами остаётся черновиком. Страницы собираются в тетрадь.
- Награды только внешние: перья (гусиное, стальное, перьевая ручка), чернила (киноварь). На сложность не влияют.
- В викторинах неверный выбор оставляет кляксу на карточке.
- Есть режим без давления: без чернил и клякс.
- Кляксы рисуются SVG-фильтром с турбулентностью (`feTurbulence`), каждая уникальна.

## Dependencies

Локально пакеты ставятся через **yarn 1.22**, а релиз в CI через `npm ci`. В репозитории оба lock-файла: после изменения зависимостей должны обновиться оба (`yarn add`, затем `npm i`), иначе `npm ci` уронит релиз.

## Architecture

Vue 3 Composition API (`<script setup lang="ts">`), TypeScript strict, Vite, alias `@` → `src/`.

### Слои

- **`src/views/<PageName>/pageName.vue`**: страницы, регистрируются в `src/router/index.ts`.
- **`src/api/*.ts`**: «API»-слой, async-функции читают локальные JSON из `src/jsons/` и возвращают типизированные ответы. Сетевых запросов нет. Каждая функция экспортирует свой тип ответа.
- **`src/jsons/*.json`**: датасеты (тексты, задания).
- **`src/configApp.ts`**: объект `appVars` с доменными константами (запас чернил, порог кляксы и т.п.). Не хардкодить эти числа в компонентах.
- **`src/composables/*.ts`**: чистые утилиты.
- **`src/components/`**: переиспользуемые компоненты:
  - `Widgets/<Name>/widget<Name>.vue`: крупные блоки страниц;
  - `Ui/<Name>/ui<Name>.vue`: мелкие UI-элементы.

### Стили

- CSS Modules: каждый `.vue` со стилями имеет парный `<имяФайла>.module.scss`, импортируется как `styles`; классы в BEM-подобной нотации `block__element`.
- Глобальные CSS-переменные проекта имеют префикс `--ink-`.

### Соглашения

- Имена файлов компонентов в camelCase, каталоги в PascalCase.
- Типы с префиксом `T` (`TPayload`, `TTextData`).
- Пропсы через `defineProps<{...}>()`, в шаблоне обращение через `props.x`.

## Code style

- Пробелы внутри скобок: `if ( !value )`, `new Date( x )`, `fn( a, b )`, `for ( let i = 0; ... )`.
- Явные TS-аннотации на переменных: `const d: Date = new Date( base )`.
- Ранний return всегда в блоке `{}` на отдельной строке, не однострочно.
- Пустые строки между логическими блоками внутри функций.

## Тексты

- Никаких интонационных тире: только там, где тире нужно грамматически. Иначе запятая, двоеточие или точка.
- «Достижения», а не «ачивки»; «серия», а не «стрик».
